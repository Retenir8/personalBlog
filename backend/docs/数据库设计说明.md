# 唐社长者学院选课平台数据库设计说明

本文档说明 `resources/schema.sql` 中 PostgreSQL 数据库结构的设计思路、关键字段及约束设置，便于研发同学理解并后续扩展。

## 1. 设计原则

- **PostgreSQL 优化**：全部类型、约束和默认值均按照 PG 最佳实践设置，例如 `BIGSERIAL` 主键、`TIMESTAMPTZ` 记录时间、`CHECK` 约束限定状态枚举等。
- **简洁可维护**：仅保留业务必需字段，避免过度设计，满足小规模项目快速上线。
- **软删除与状态区分**：通过 `is_deleted` 与 `status` 字段区分“是否被删除”和“业务状态”，方便数据恢复和后台筛选。
- **自动更新时间**：触发器统一维护 `updated_at`，避免应用层忘记更新。

## 2. 公共触发器

```sql
CREATE OR REPLACE FUNCTION trigger_set_timestamp()
CREATE TRIGGER trg_xxx_set_timestamp BEFORE UPDATE ...
```

- `trigger_set_timestamp()`：任意表在更新前自动写入当前时间至 `updated_at`。
- `users`、`courses` 表分别创建触发器，保证更新时间一致性。

## 3. 核心表结构

### 3.1 `users`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user_id` | `BIGSERIAL` | 主键，自增 |
| `name` | `TEXT` | 登录用姓名，设唯一约束，回避重复注册 |
| `password_hash` | `TEXT` | 密码哈希值（建议 bcrypt/argon2） |
| `gender` | `TEXT` | 性别，保留文本以支持“男/女/其他” |
| `date_of_birth` | `DATE` | 出生日期，便于动态计算年龄 |
| `phone` | `VARCHAR(20)` | 手机号，可空，建立唯一索引（忽略空值） |
| `avatar_url` / `hobbies` / `health_condition` | `TEXT` | 用户资料信息 |
| `last_login_at` | `TIMESTAMPTZ` | 最近登录时间 |
| `status` | `SMALLINT` | 账号状态，`CHECK (status IN (0,1))`，0=正常、1=禁用 |
| `role` | `TEXT` | 角色，默认 `'user'`，`CHECK (role IN ('user','admin'))` |
| `is_deleted` | `BOOLEAN` | 逻辑删除标记 |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | 创建/更新时间，默认 `NOW()` |

**索引**：

- `users_phone_unique`：`phone` 唯一索引（忽略空值），便于手机号登录/搜索。

**设计说明**：

- 注册/登录接口使用姓名与密码，因此 `name` 唯一。
- 使用 `date_of_birth` 替代直接存储年龄，保证数据可更新。
- `role` 字段支持将管理员与普通用户放在同一表管理。

### 3.2 `courses`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `course_id` | `BIGSERIAL` | 主键，自增 |
| `title` | `TEXT` | 课程名称 |
| `category` | `TEXT` | 分类名称（文本存储，便于灵活扩展） |
| `description` | `TEXT` | 课程简介 |
| `start_date` / `end_date` | `DATE` | 开课与结课日期，`CHECK` 限制结课日期不早于开课 |
| `class_time` | `TEXT` | 上课时间描述，如“每周三上午9:00-10:30” |
| `location` | `TEXT` | 上课地点（纯文本保存地点信息） |
| `capacity` | `INTEGER` | 招生上限，`CHECK (capacity > 0)` |
| `status` | `SMALLINT` | 状态标识：0=未开始、1=进行中、2=已结课 |
| `image_url` / `contact_phone` | `TEXT` / `VARCHAR(20)` | 配图与联系方式 |
| `is_deleted` | `BOOLEAN` | 逻辑删除 |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | 创建/更新时间 |

**索引**：

- `courses_category_idx`：分类查询场景。
- `courses_start_date_idx`：按日期排序或筛选。

**设计说明**：

- `enrolled` 不放入表内，交由视图统计，避免并发更新复杂度。
- `location` 按需求仅保存字符串，不做地理定位扩展。

### 3.3 `course_enrollments`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `enrollment_id` | `BIGSERIAL` | 主键，自增 |
| `user_id` | `BIGINT` | 关联 `users(user_id)`，级联删除 |
| `course_id` | `BIGINT` | 关联 `courses(course_id)`，级联删除 |
| `created_at` | `TIMESTAMPTZ` | 报名时间 |

**约束与索引**：

- `UNIQUE (user_id, course_id)`：防止重复报名。
- `course_enrollments_course_idx`：管理员查看某课程报名名单时使用。
- `course_enrollments_user_idx`：用户查询自己的报名列表。

**设计说明**：

- 级联删除保证用户或课程删除后，关联报名自动清理，保持数据一致。
- 报名时间保留，便于统计最早/最新报名情况。

## 4. 统计视图

```sql
CREATE OR REPLACE VIEW course_enrollment_summary AS ...
```

- 汇总每门课程的报名人数 (`COUNT(*)`)，与课程详细信息拼接。
- API 可以直接查询此视图替代原始表中的 `enrolled` 字段，避免手动维护计数。

## 5. 后续拓展建议

- 若需更丰富的用户角色，可将 `role` 抽象为枚举或单独关联角色表。
- 可新增 `course_tags`、`course_reviews` 等扩展表，以相同方式继续复用触发器与时间戳字段。
- 若报名人数查询压力增大，可考虑使用物化视图或后台任务维护统计字段。

如有新的字段需求或接口调整，请同步更新 `resources/schema.sql` 并修订本文档。欢迎提出改进建议。***
