# 权限控制实现说明

## 一、权限控制架构

本系统实现了基于角色的访问控制（RBAC），包含以下组件：

### 1. 角色定义
- **USER（普通用户）**：默认角色，可以访问基本功能
- **ADMIN（管理员）**：拥有所有权限，可以管理用户和课程

### 2. 核心组件

#### 2.1 `@Auth` 注解
```java
@Auth                    // 只需要登录，不限制角色
@Auth(role = Role.USER)  // 需要普通用户权限（默认）
@Auth(role = Role.ADMIN) // 需要管理员权限
```

#### 2.2 `AuthAspect` 切面
- 拦截所有带 `@Auth` 注解的方法
- 验证 Token 有效性
- 提取用户 ID 和角色信息
- 验证用户是否有权限访问接口
- 将用户信息存入请求上下文（`request.setAttribute`）

#### 2.3 `JWTUtil` 工具类
- 生成包含角色信息的 Token
- 从 Token 中提取用户 ID 和角色
- 支持 Access Token 和 Refresh Token

#### 2.4 `ForbiddenException` 异常
- 用于表示权限不足
- 返回 HTTP 403 状态码

## 二、权限控制策略

### 1. 接口级别权限控制（通过 @Auth 注解）

#### 公开接口（无需认证）
- `POST /api/register` - 注册
- `POST /api/login` - 登录

#### 普通用户接口（需要登录）
```java
@Auth  // 或 @Auth(role = Role.USER)
```
- `GET /api/courses` - 获取课程列表
- `GET /api/course/:id` - 获取课程详情
- `POST /api/enroll` - 报名课程
- `DELETE /api/enroll/:id` - 取消报名

#### 管理员接口（需要管理员权限）
```java
@Auth(role = Role.ADMIN)
```
- `POST /api/course` - 新增课程
- `PUT /api/course/:id` - 修改课程
- `DELETE /api/course/:id` - 删除课程
- `GET /api/enroll/course/:course_id` - 获取课程报名名单
- `GET /api/admin/users` - 获取所有用户列表
- `DELETE /api/admin/user/:id` - 删除用户

### 2. 数据级别权限控制（在 Service 层实现）

#### 用户信息访问控制
```java
// UserService.getUserInfo()
// 规则：普通用户只能查看自己的信息，管理员可以查看所有用户信息
if (!Role.ADMIN.getValue().equals(currentUserRole) && !userId.equals(currentUserId)) {
    throw new ForbiddenException("无权访问其他用户信息");
}
```

#### 用户信息修改控制
```java
// UserService.updateUserInfo()
// 规则：普通用户只能修改自己的信息，管理员可以修改所有用户信息
if (!Role.ADMIN.getValue().equals(currentUserRole) && !userId.equals(currentUserId)) {
    throw new ForbiddenException("无权修改其他用户信息");
}
```

#### 报名信息访问控制
```java
// EnrollmentService.getUserEnrollments()
// 规则：普通用户只能查看自己的报名记录，管理员可以查看所有报名记录

    throw new ForbiddenException("无权访问其他用户的报名信息");
}
```

#### 取消报名控制
```java
// EnrollmentService.cancelEnrollment()
// 规则：普通用户只能取消自己的报名，管理员可以取消任何报名
if (!Role.ADMIN.getValue().equals(currentUserRole) && !enrollmentUserId.equals(currentUserId)) {
```

## 三、实现细节

### 1. Token 结构
```json
{
  "user_id": "123",
  "role": "user",  // 或 "admin"
  "exp": 1234567890
}
```

### 2. Controller 层实现模式
```java
@Auth
@GetMapping("/{userId}")
public ResponseEntity<Result> getUserInfo(
        @PathVariable String userId,
        HttpServletRequest request
) {
    // 从请求上下文获取当前用户信息
    String currentUserId = (String) request.getAttribute("userId");
    String currentUserRole = (String) request.getAttribute("role");
    
    // 调用 Service 层，传递权限信息
    return userService.getUserInfo(userId, currentUserId, currentUserRole);
}
```

### 3. Service 层实现模式
```java
public ResponseEntity<Result> getUserInfo(String userId, String currentUserId, String currentUserRole) {

        throw new ForbiddenException("无权访问其他用户信息");
    }

    // ...
}
```

## 四、安全最佳实践

### 1. 防止越权访问
- ✅ 所有涉及用户数据的接口都必须验证当前用户是否有权限访问
- ✅ 不能仅依赖 URL 参数中的 userId，必须与 Token 中的 userId 对比
- ✅ 管理员可以访问所有数据，普通用户只能访问自己的数据

### 2. 错误信息处理
- ✅ 权限不足返回 403 Forbidden
- ✅ 未登录返回 401 Unauthorized
- ✅ 资源不存在返回 404 Not Found
- ✅ 不要在错误信息中泄露敏感信息

### 3. Token 安全
- ✅ Token 包含角色信息，避免每次请求都查询数据库
- ✅ Token 有过期时间（24小时）
- ✅ Refresh Token 有更长的过期时间（2小时）
- ⚠️ 建议：生产环境应使用 HTTPS 传输 Token

## 六、使用示例

### 1. 普通用户访问自己的信息
```bash
# 登录获取 Token
POST /api/login
{
  "username": "zhangsan",
  "password": "123456"
}

# 返回
{
  "code": 200,
  "data": {
    "token": "eyJhbGc...",  // 包含 user_id=1, role=user
    "user": { "user_id": 1, "name": "张三" }
  }
}

# 访问自己的信息（成功）
GET /api/user/1
Authorization: Bearer eyJhbGc...

# 访问其他用户信息（失败）
GET /api/user/2
Authorization: Bearer eyJhbGc...
# 返回 403: "无权访问其他用户信息"
```

```bash
    "user": { "user_id": 999, "name": "管理员" }
  }

# 访问任何用户信息（成功）
```

## 八、常见问题

### Q1: 为什么要在 Service 层再次验证权限？
A: 接口级别的 `@Auth` 注解只能控制"是否需要管理员权限"，但无法控制"用户是否可以访问特定数据"。例如，`GET /api/user/:id` 接口普通用户可以访问，但只能访问自己的数据，这需要在 Service 层进行数据级权限验证。

### Q2: 如何创建管理员账号？
A: 方式一：直接在数据库中修改用户的 role 字段为 'admin'
方式二：创建专门的管理员注册接口（需要超级管理员权限或初始化脚本）

### Q3: Token 过期后怎么办？
A: 使用 Refresh Token 刷新 Access Token，或者重新登录。

### Q4: 如何防止 Token 被盗用？
A: 
- 使用 HTTPS 传输
- 设置合理的过期时间
- 实现 Token 黑名单机制（可选）
- 记录用户登录 IP 和设备信息（可选）
