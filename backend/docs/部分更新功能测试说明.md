# 用户信息部分更新功能测试说明

## 功能概述

已实现用户信息的部分更新功能，系统现在只会更新请求中包含的字段，未包含的字段将保持不变。

## 实现细节

### 1. 修改的文件

- **UserMapper.java**: 添加了 `updateUserSelective` 方法，使用动态 SQL 实现部分更新
- **UserSqlProvider.java**: 新增的 SQL 提供者类，生成动态 SQL 语句
- **UserService.java**: 修改 `updateUserInfo` 方法，使用部分更新逻辑
- **UserDTO.java**: 增强 `toUser` 方法，特别处理 Gender 字段的转换

### 2. Gender 字段特殊处理

Gender 字段支持以下输入格式：
- 枚举名称（大小写不敏感）: `"MALE"`, `"FEMALE"`, `"UNKNOWN"`
- 中文值: `"男"`, `"女"`, `"未知"`
- `null` 或空字符串: 不更新该字段

### 3. 部分更新逻辑

- 只有请求体中包含的非 null 字段才会被更新
- 未包含在请求中的字段保持原值不变
- 空字符串会被视为有效值（除了 Gender 字段）

## 常见问题

### Q1: Gender 字段更新失败
**原因:** 可能传入了无效的值
**解决:** 确保使用以下有效值之一：
- **中文值（推荐）**: `"男"`, `"女"`, `"未知"`
- 枚举名（兼容）: `"MALE"`, `"FEMALE"`, `"UNKNOWN"`

**前端应该发送中文值**，例如：
```json
{
  "gender": "男"
}
```

### Q2: 字段被意外清空
**原因:** 可能在请求中显式传入了 `null` 值
**解决:** 不要在请求中包含不想更新的字段

### Q3: 所有字段都被更新了
**原因:** 可能使用了旧的更新方法
**解决:** 确保代码已更新，使用 `updateUserSelective` 方法

## 技术实现说明

### 动态 SQL 生成

使用 MyBatis 的 `@UpdateProvider` 注解和 `SQL` 类动态生成 SQL 语句：

```java
public String updateUserSelective(User user) {
    return new SQL() {{
        UPDATE("users");
        
        if (user.getUsername() != null) {
            SET("username = #{username}");
        }
        if (user.getGender() != null) {
            SET("gender = #{gender}");
        }
        // ... 其他字段
        
        WHERE("user_id = #{userId}");
    }}.toString();
}
```

这样生成的 SQL 只包含非 null 字段的更新语句。

### Gender 字段转换逻辑

```java
Gender gender = null;
if (userDTO.getGender() != null && !userDTO.getGender().trim().isEmpty()) {
    try {
        // 尝试枚举名称转换
        gender = Gender.valueOf(userDTO.getGender().toUpperCase());
    } catch (IllegalArgumentException e) {
        // 尝试中文值匹配
        for (Gender g : Gender.values()) {
            if (g.getValue().equals(userDTO.getGender())) {
                gender = g;
                break;
            }
        }
    }
}
```

这个逻辑确保了 Gender 字段的灵活性和健壮性。
